# Project Overview

You are upgrading an existing project called JS-Portable-Queue.

This project already works and already contains:

* HTML frontend
* Vanilla JavaScript architecture
* Queue management system
* User authentication system
* Admin panel
* Public display board
* Multiple queue pools
* Multiple counters
* Audit logging

DO NOT redesign the application from scratch.

DO NOT replace the frontend with React, Vue, Angular, Next.js, Nuxt, or any other framework.

The goal is to preserve the existing UI and business logic while replacing browser localStorage with a shared multi-device backend.

Socket.IO

# Refactoring Strategy

Do NOT directly call localStorage.

Create service functions.

Example:

getQueueState()

saveQueueState()

getUsers()

saveUsers()

getLogs()

appendLog()

getSession()

saveSession()

Every existing module should call these abstractions.

The backend implementation may change later without modifying business logic.

# Real-Time Updates

Current system uses:

window.storage

and

JSQ_Queue.onChange()

Replace synchronization with:

Socket.IO

When queue data changes:

Server emits:

Frontend receives:

queueUpdated

Existing rendering functions should refresh.

The display board should update immediately.

No page refresh.

No polling.

No browser reload.
